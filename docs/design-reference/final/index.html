Golden Hour — app vs canvas

Left: the Claude Design frame (docs/design-reference/frames). Right: the running app captured by parity-check.mjs at the same width. Style parity is proved by the assertion files in docs/design-reference/assertions; this page is the visual record.

Remaining deviations (from the plan, §5)

  1. Stats copy — "412 appeared in search / 38 profile views" are canvas figures. The app shows real numbers, and "Appeared in search" is labelled as on-site search until Google Search Console is connected (blocked on the manual GCP step in CLAUDE.md).
  2. Discipline counts — the canvas hard-codes count: 9 etc. The app computes real counts (published + mock).
  3. Town suggestions — the canvas uses a 24-town list; the app uses the real postcode/area data via the existing autocomplete API.
  4. Testimonials — canvas placeholders; the app renders real testimonials rows and hides the section when there are none (never an empty band).
  5. Pronouns — canvas headings say "she/her"; the app uses the coach's first name instead of guessing.
  6. Map — canvas is a placeholder; the app plots real PostGIS results on OSM tiles.
  7. Dashboard tabs — canvas uses client state; the app uses real routes so links, refresh and back/forward work. Visually identical.
  8. Delete my account — the canvas is a bare link; the app confirms first.
  9. Pages without a canvas (§1 last row) get the tokens and the header/footer, nothing invented.
